## 一、结论(一句话)

**机位四元数换算是对的:当前 cam_pos_0 就是真值 Battle0 经"环境 X 镜像 + Unity+Z 前→Godot−Z 前"的正确换算值(矩阵级证明 + 运行时实测逐位一致);两边画面并非互为镜像。** 画面布局差异的真实来源是:① 相机 x 未随环境取负(项目既定"位置沿用原值"约定),视点相对镜像环境横移 1.47m,属平移视差而非翻转;② 环境 FBX 导入的内容差(南侧楼梯间公告板等);③ 雾/色调。G0 出生锥打近墙大半是原作设计本身(真值同样向 2.7m 外的楼梯间墙面射线),Godot 侧更近(1.27m)是"位置未镜像"的连带后果,与朝向无关。`x<0→+0.3` 修正确实未随镜像翻转(应改 `x>0→−0.3`),是唯一坐实的镜像类偏差,但仅 0.3m、低严重度。

## 二、证据链

1. **真值 Battle0 运行时姿势 = 场景 YAML 记录值**,双重确认:
   - `school_day.unity:109769-770`:pos (−0.7353256, 1, −10.270634),quat (−0.04023208, 0.4902658, 0.022659225, 0.87034905);父链 StoryLevel1GamePlay 在原点 identity(:109552-565),local==world。
   - Unity 运行时日志 `tools/logs/unity_l1_cams.log:1251`:`L1 CAM G4 pos=(-0.7353,1,-10.2706) quat=(-0.040232,0.490266,0.022659,0.870349) fov=45` —— 运行时相机逐位等于 YAML 记录值。
   - 关键机制:Battle0 的 cm 子物体**只有 Transposer(guid ac0b09e7,:109964),没有 Composer(guid 1e8b78ac)**;全场景只有 vcam1 的 cm 含 Composer(:118110)。`m_LookAt=Neck`(:109795)对战斗机位是**空挂**——故"Battle0 运行时盯 Neck"假设不成立,记录值即运行时朝向(yaw +58.8° 斜视楼梯间)。
   - 附:Neck 静态 (0.1475,1.3899,10.0886) 假设方向 = (0.8828, 0.3899, 20.3592) → yaw +2.48°/pitch +1.10°,与真值截图(画面中心落在约 8m 外楼梯间,而非 20m 走廊深处)不符,再次佐证 LookAt 未生效。
2. **环境镜像属实(数据级)**:两边 env 同名节点配对,|x|>0.5 的 46 对中 43 对严格 x 取反、0 对不变(其余 3 对是组原点占位)。例:楼梯间点光 Unity (+8.5, 3.66/8.2, −8.5) ↔ Godot (−8.5, …);走廊窗 Unity x=−2 ↔ Godot x=+2;教室墙 Unity x=+2 ↔ Godot x=−2。
3. **正确换算公式推导**(四元数 (x,y,z,w),两边共用 Hamilton 约定):
   世界映射 M=diag(−1,1,1)(x 取反),相机前向约定差 F=diag(1,1,−1)(Unity 看 +Z,Godot 看 −Z)。
   要求同画面 ⟺ Godot 相机系坐标 d = F·c(c 为 Unity 相机系坐标) ⟹ **R_g = M·R_u·F**。
   矩阵乘法合成到四元数分量:M·R_u·M = (x,−y,−z,w)(镜像共轭),再右乘 M·F=Rot180Y=(0,1,0,0),
   合并结果:**q_g = (z, w, x, y)**。数值验证:q_g 矩阵与 M·R_u·F 最大分量差 1.7e−7。
   ⟹ Battle0 正确 Godot quat = **(0.022659225, 0.87034905, −0.04023208, 0.4902658)**(yaw −58.8°,即 Godot 欧拉约定 121.2°,望向镜像后的 −x 楼梯间一侧)。
4. **Godot 现状逐位命中**:level1_battle.tscn:61 的 cam_pos_0 矩阵三元组 = 上述 quat 的矩阵行(最大差 4.9e−7);运行时实测(本次核查实跑)`group0 cam pos=(−0.7353256, 1, −10.27063) quat=(0.022659294, 0.870349, −0.04023224, 0.49026585) fov=45`,与正确值最大分量差 1.6e−7。**l1_visual.md:47 的"自洽 ✓"判决正确;开发 agent 的"镜像错了"不成立。**
5. **实拍对号**:本次核查实跑当前工作树截图 `_verdict_g0.png` 与历史审计图(cam_G0/hud_25s/gun_25s,2026-06 与 2026-09 两批)完全一致:楼梯居中、扶手+公告板在楼梯上方、左侧墙带单门、右侧双开门。用当前机位对 Godot env 全网格做视锥投影,内容逐项对上:楼梯间防火门左扇把手投影 ndc (−0.28, −0.24) vs 图上实测 (−0.29, −0.23);扶手 ndc (0.32, 0.23);楼梯间 Paper ndc (−0.01, 0.37);右扇防火门 ndc +0.93~+1.06(画面右缘双开门)——当前 Godot 画面就是该换算值该有的画面。
6. **等价定理(矩阵推导 + 数值抽查)**:Godot(镜像 env, 相机 p_u, R_g=M·R_u·F) 渲染结果 ≡ Unity(原始 env, 相机 M·p_u=(+0.735, 1, −10.27), R_u) 渲染结果,逐像素相等。即:**当前 Godot 画面 = 真值相机挪到走廊另一侧(x=+0.735)所拍**,不是真值的镜像翻转。
7. **"非镜像"的直接视觉证据**:两边楼梯扶手都是"左下→右上"走向(翻转应反向);枪/HUD 均在右下;右侧均为墙+门。真正互换的是画面左缘内容(见下),那是视点横移造成的。
